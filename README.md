## 这是什么

一个 Minecraft: Java Edition 的 Android 启动器。

启动核心基于 PojavLauncher 的 JNI 层，界面用 Jetpack Compose 与 Material Design 3 写。它做的核心事情只有三件：把 Java 运行时准备好、把游戏文件准备好、把 JVM 拉起来并把画面交给渲染器。剩下的所有功能都是为了让这三件事顺畅。

PE 是 Pure Edition 的意思。这个版本砍掉了全部装饰性渲染——没有雨滴，没有粒子，没有节日彩蛋，没有淡入淡出，没有滑动转场。点一下就是一下，页面瞬间切换。理由很简单：手机的资源是有限的，与其花在让界面看起来花哨，不如全部让给游戏。

## 设计取舍

启动器这类工具，长时间待在后台、频繁被唤起、和游戏抢占内存。在这类场景下，动画和特效不是加分项，而是负担：

- 每帧多一次全屏混合，就少一点给区块加载的余量
- 每次页面切换多 300ms 过渡，就多一次用户等待
- 每个装饰性绘制层，都要多占一块显存

所以这个版本的选择是：**界面元素直接呈现，不做任何中间过渡**。

具体删掉的东西：

| 移除项 | 原因 |
|---|---|
| 雨滴 / 水痕渲染层 | 全屏逐像素着色，GPU 开销最大的一项 |
| 节日特效（雨、雪、烟花、萤火虫、蝙蝠、爱心） | 常驻粒子系统，CPU 与 GPU 双开销 |
| 节日标题替换 | 每日检查与文字重绘 |
| 液态玻璃高光 | 额外的绘制层与混合 |
| 页面切换过渡 | 纯粹的等待 |
| 淡入淡出、滑动、缩放 | 同上 |
| 加载骨架闪烁 | 无限循环动画，持续触发重绘 |

保留下来的：模糊背景（它同时承担可读性职责）、主题配色、自定义背景图。这些不是装饰，是界面能看清、能用的前提。

## 功能

### 游戏与版本

- 从官方源拉取版本清单，一键安装任意正式版、快照版、旧版
- 支持 Forge、NeoForge、Fabric、Quilt、OptiFine、LiteLoader 等加载器
- 版本隔离：每个版本有独立的模组目录、配置文件、存档，互不干扰
- 版本复制与重命名，方便开多个实例测试不同模组组合
- 启动前可覆盖 JVM 参数、游戏参数、窗口尺寸
- 游戏目录可指定到外置存储

### 账号

- 离线账号（自定义用户名，本地生成 UUID）
- 微软账号 OAuth 2.0 登录，token 自动刷新
- 第三方认证服务器（Authlib-Injector）支持，可对接自建皮肤站
- 多账号并存，随时切换
- 皮肤与披风查看、替换

### 下载

- 游戏本体、依赖库、资源文件、版本 JSON 全量下载
- 模组、整合包、资源包、光影包、世界存档
- 支持 CurseForge 与 Modrinth 的内容检索与一键安装
- 整合包格式支持：CurseForge zip、Modrinth mrpack、通用压缩包
- 下载源三档可选：官方源 / 镜像源 / 自动测速选择
- 分块多线程下载，断点续传，失败自动重试
- 全局下载任务队列，可暂停、恢复、取消、重排

### 渲染

- Vulkan 后端
- OpenGL 后端
- Zink：在 Vulkan 之上跑 OpenGL
- 渲染器插件机制，可加载独立的渲染插件
- 每个版本可独立指定渲染器与参数
- 驱动与兼容层可选：MobileGlues、NG-GL4ES、SimpleFPEWrapper、ANGLE

### 运行环境

- Java 运行时自动管理：JRE 8 / 17 / 21 / 25 按版本需求自动匹配
- 运行时按 ABI 与架构精简，只保留当前设备需要的部分
- 首次使用的运行时本地解压，之后直接复用
- 内存上限、GC 参数可调

### 操作

- 游戏内虚拟按键：按键、摇杆、视角区，全部可拖动缩放
- 虚拟鼠标模式，适配需要精确点击的模组界面
- 手柄映射
- 布局可保存多套，随时切换
- 外接键盘鼠标直接可用

### 工具

- 内置文件管理器：浏览、复制、移动、重命名、删除、压缩、解压
- 游戏日志实时查看，支持按级别过滤
- 崩溃日志收集、导出、一键复制
- 后台任务保活，避免下载中途被系统杀掉
- 通知栏进度提示

### 界面

- Material Design 3
- 动态取色（Android 12+ 跟随壁纸）
- 多套内置配色方案
- 自定义强调色与调色风格
- 自定义背景图或背景视频
- 深色 / 浅色主题跟随系统
- 横竖屏自适应，平板与折叠屏可用
- 全屏沉浸模式

## 上手流程

第一次用的话，按这个顺序走：

1. **装应用**：下载 APK 安装，首次打开会解压运行库，等几分钟
2. **加账号**：设置里添加账号。有正版就登微软，没有就建离线账号
3. **装版本**：进下载页，选一个版本装。想玩模组就顺手装对应的加载器
4. **调设置**：进版本设置，分配内存（一般给设备内存的三分之一到一半），选渲染器
5. **启动**：回主页点启动，第一次进游戏会生成资源文件，慢一点属正常

想开光影的话，需要额外装光影加载器（Iris 或 OptiFine），把光影包放进 `shaderpacks` 目录，然后在游戏内视频设置里选。

## 系统要求

| 项目 | 最低 | 建议 |
|---|---|---|
| 系统版本 | Android 8.0（API 26） | Android 12 及以上 |
| 架构 | arm64-v8a | arm64-v8a |
| 内存 | 4 GB | 8 GB 及以上 |
| 存储 | 2 GB 可用 | 8 GB 可用（含模组与存档） |
| GPU | 支持 OpenGL ES 3.0 | 支持 Vulkan 1.1 |

内存分配建议：设备 4 GB 给游戏 1 GB，6 GB 给 1.5 GB，8 GB 给 2 GB，12 GB 以上给 3–4 GB。分配过多反而会因为系统回收而卡顿。

## 安装

1. 在 [Releases](../../releases) 页面下载最新的 `CMCLauncher-Debug-1.0.0-arm64-v8a.apk`
2. 允许安装未知来源应用，安装 APK
3. 打开应用，等待首次解压完成

包名：`com.cmc.launcher.pe`

首次启动的解压过程可能需要 1–5 分钟，取决于存储速度。期间请不要退出应用。

## 常见问题

**启动后黑屏，只有声音**

多半是渲染器不兼容。进版本设置换一个渲染器（Vulkan 换 OpenGL，或反过来），再试。

**卡在"正在解压"很久**

存储速度慢或者空间不足。检查剩余空间，机械存储或低速闪存会明显更慢。如果超过十分钟没有进展，清掉应用数据重来。

**提示 Java 版本不匹配**

不同 Minecraft 版本需要不同 JRE：1.16 及以下用 Java 8，1.17–1.20.4 用 Java 17，1.20.5 及以上用 Java 21，26.1 之后部分版本需要 Java 25。启动器一般会自动匹配，如果手动改过就在这里改回来。

**装了模组但游戏里没有**

先确认模组版本和游戏版本对得上，再确认放进了正确的 `mods` 目录（开启了版本隔离时是版本独立的目录）。加载器类型也要匹配，Forge 的模组装不进 Fabric。

**联机进不去朋友的房间**

先确认网络能连通。局域网联机需要同一网段；公网联机建议用专门的联机工具或自建服务端。部分服务端需要正版验证，离线账号会被拒绝。

**下载一直失败或极慢**

切换下载源，或者关掉自动测速手动选镜像。部分资源在特定网络环境下确实拉不动，换个时间再试也可能有效。

**游戏很卡**

先降渲染距离和视距，再考虑换渲染器，最后才是加内存。大多数卡顿不是内存不够，是 GPU 撑不住分辨率与视距。

**手柄没反应**

在按键设置里确认已识别到手柄，并且当前布局绑定了手柄输入。部分手柄需要先在系统层面被识别。

## 数据目录

应用数据位于 `/sdcard/Android/data/com.cmc.launcher.pe/`（Android 11 以上受分区存储限制，用应用内文件管理器访问更省事）。

游戏文件默认在 `/sdcard/CMCLauncherPE/`，可在设置里改。目录结构大致如下：

```
CMCLauncherPE/
├── versions/          # 各版本游戏文件
│   └── <版本名>/
│       ├── mods/      # 版本的模组目录
│       ├── config/    # 版本的配置目录
│       ├── saves/     # 版本的存档
│       └── shaderpacks/
├── libraries/         # 公共依赖库
├── assets/            # 游戏资源文件
└── <版本名>.json      # 版本配置
```

## 构建

### 环境要求

- Android Studio 或命令行 Gradle 环境
- Android SDK：最低 API 26，目标 API 35
- JDK 21
- Rust 工具链（含 Android 目标）
- Android NDK

### 命令行构建

```bash
git clone https://github.com/ylh440104/CMCLauncher-PE.git
cd CMCLauncher-PE
./gradlew :CMCLauncher:assembleDebug -Darch=arm64
```

产物位于 `CMCLauncher/build/outputs/apk/debug/`。

`-Darch` 可选 `arm64`、`arm32`、`x86_64`、`all`，决定打包哪些架构的本地库与运行时。

### 自动构建

仓库已配置 GitHub Actions：推送到 `main` 分支自动触发构建，成功后自动发布到 Releases。也可以在 Actions 页面手动触发。
